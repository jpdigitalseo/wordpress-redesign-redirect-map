WordPress redesign redirect map: a 5-column sheet that keeps rankings

Most traffic drops after a redesign come from one thing: old URLs that used to rank now return 404. A redirect map fixes that before launch. It doesn't need a tool. A spreadsheet with five columns is enough for a typical 10–60 page small-business site.

The five columns

ColumnWhat goes in it
Old URLEvery URL from the current sitemap, plus any URL with clicks in Search Console over the last 12 months.
New URLThe closest matching page on the new site. Same topic, not just the homepage.
Statuskeep (URL unchanged), 301 (moved), or 410 (gone on purpose, no match).
ReasonOne short line, e.g. "merged into services page" or "old promo, expired".
CheckedThe date someone loaded the old URL after launch and confirmed it lands on the new URL in one hop.

How to fill it in

  1. Export the old URLs first. Pull /sitemap_index.xml (or /wp-sitemap.xml) and the Search Console Pages report. Merge and de-duplicate.
  2. Keep every URL you can. The safest redirect is no redirect. If the slug can stay the same on the new site, mark it keep.
  3. Match by topic, not by convenience. Sending everything to the homepage is treated like a soft 404. Point each old page at the page that answers the same question.
  4. Avoid chains. If an old URL already redirects, point the original straight at the final new URL.
  5. Load the 301 rules before DNS or theme switch. A redirect plugin or server rules should be live the minute the new design is.

The launch-day check

Paste the Old URL column into a text file and run a quick loop:

while read u; do
  curl -s -o /dev/null -w "%{http_code} %{redirect_url} $u\n" "$u"
done < old-urls.txt

Every line should show 200 (kept) or 301 with the new URL from your sheet. Anything showing 404 or 302 gets fixed the same day, then the "Checked" column gets a date.

What not to change at the same time

Keep titles, H1s and main body copy close to the old versions on pages that already rank. Change the design first, let rankings settle for a few weeks, then rewrite copy. Changing URLs, layout and words in one launch makes it impossible to tell what caused a drop.
